Vexel.Telegram v2 - contexts / Feedback / AddTelegramBot end-to-end run

A real generic host wired only with `services.AddTelegramBot(_ => token)` long-polls an
in-process fake Telegram Bot API over HTTP. Handlers inject the concrete contexts
(MessageContext / CallbackContext / InlineQueryContext) and reply through Feedback.

What to look for:
  * "telegram-api  <- bot calls ..." lines: what Telegram actually received from the bot.
  * one answerCallbackQuery even though the handler answered twice (first-wins idempotence).
  * editMessageText targets the bot-authored message (message_id=9001) behind the button.
  * "Failed to resolve raw update handler" errors are expected: a raw handler asking for a
    context of the wrong update kind is skipped without taking its siblings or the lane down.
  * Per-update DI scope identities: a distinct holder + Feedback per update, each bound to its
    own update id, and the callback-answered latch never leaking into the next update.
